# LBK Launcher

Electron 44 + React 19 desktop app (Windows, macOS, Linux incl. Steam Deck) that installs Ukrainian game localizations. Catalog lives in a local better-sqlite3 DB synced from Supabase; the installer downloads and extracts archives into detected game folders and wires up Steam integration. UI copy is Ukrainian, code identifiers are English. `package.json` version is currently 2.23.1.

## Commands

```bash
pnpm dev              # prebuild (bridge + spellfix) + electron-vite dev, renderer on port 5173
pnpm build            # electron-vite build → out/{main,preload,renderer}
pnpm prebuild         # pnpm build:bridge && node scripts/build-spellfix.js
pnpm type-check       # tsc --noEmit, then tsc -p for each packages/lbk-bridge-* — CI gate 1
pnpm test:unit        # pretest:unit builds the bridge, then vitest run — CI gate 2
pnpm lint             # eslint . — CI gate 3
pnpm format:check     # biome check --max-diagnostics=200 . — CI gate 4
pnpm find-unused      # knip — CI gate 5, an unused export fails the build
pnpm format           # biome check --write .
pnpm dist:win|linux|mac        # electron-builder → release/<version>/
pnpm dist:mac:local            # env-cmd + CSC_IDENTITY_AUTO_DISCOVERY=false
pnpm test:e2e         # playwright over CDP :19222 against the packaged app
pnpm build:bridge     # wireit: build packages/* (CDP ops and achievement page IIFEs, Millennium ttc index.js/webkit.js, Decky rollup) only when their inputs changed; gitignored output, fingerprints and cache in .wireit/
pnpm dev:bridge       # the same builds in watch mode; `pnpm dev` does not watch packages/
```

Each package's `wireit` block in its `package.json` lists the inputs (`files`, the lockfile, the workspace packages it reads) and `output`; a build input missing there leaves a stale bundle after `pnpm dev` / `pnpm test:unit`, so add it when a build starts reading a new file. `.github/workflows/ci.yml` runs `pnpm build:bridge` after install (the `?raw` ops import, tests and knip need the output), then gates 1–5 in that order on Node 24.21.0 / pnpm 11.4.0. `--publish never` is not in the scripts — `release.yml` appends it to `pnpm dist:*`. `.husky/pre-commit` runs `npx lint-staged`, which runs only `biome check --write --no-errors-on-unmatched` on staged `*.{js,ts,tsx,json,css,scss}`; type-check, eslint and knip do not run locally.

## Architecture

Three processes plus a DB worker thread. `electron.vite.config.ts` builds **two** main-process rollup entries: `index` (`src/main/index.ts`) and `db-worker` (`src/main/db/db-worker.ts`). `better-sqlite3` and `electron-liquid-glass` are rollup externals; the ESM-only `got`, `electron-store`, `fast-vdf`, `resedit`, `p-timeout`, `p-memoize`, `p-limit` and `p-wait-for` are deliberately bundled (`externalizeDeps.exclude`) — the main build is CJS, and externalized they arrive through `require(esm)` as a namespace, so a default import hits rollup's interop (`got.stream is not a function`, `ElectronStore is not a constructor`) on first use, at runtime only. `binarykvparser` is bundled too: it ships `long` as a bundledDependency, which electron-builder drops from `app.asar` (the packaged app crashed on start). `bundled-dependencies.test.ts` fails for any dependency that ships bundledDependencies, and for any ESM-only one (no `require` condition on its root export) missing from a build's own `exclude`: the main build's for what `src/main`, `src/shared`, `src/lib` or `packages/lbk-bridge-core/src` imports, the `preload:` block's (none today, so it externalizes every dependency) for what `src/preload/index.ts` reaches through relative and `@/` value imports.

**Only `@` is aliased in the main and preload builds.** `@renderer`, `@components`, `@store` and `@resources` exist solely in the renderer build even though `tsconfig.json` declares all five, and vite does not read tsconfig paths — a value import through one of them from main/preload passes `pnpm type-check` and then fails at build. Use `@/...` outside the renderer.

The whole app body lives inside the single-instance-lock `else` branch of `src/main/index.ts` (`if (!gotTheLock) { app.quit() } else { … }`). Put new app wiring inside it, or it runs in the doomed second instance too.

### IPC — six bridges, not one

`src/preload/index.ts` calls `contextBridge.exposeInMainWorld` six times: `electronAPI`, `windowControls`, `liquidGlassAPI`, `loggerAPI`, `api`, `storeStorage`.

- `electronAPI` is typed by the `ElectronAPI` interface in `src/shared/types.ts` (`const electronAPI: ElectronAPI = {...}` makes a missing method a compile error), and `declare global` there adds it to `Window`. The Millennium / Decky / Steam-bridge payload types (`PluginHostState`, `SteamBridgeStatus`, `MillenniumInstallResult`, `RestartSteamResult`, …) live in `src/shared/plugin-host-types.ts`; import them from there, `types.ts` only uses them in `ElectronAPI`.
- The other five are typed by hand in `src/window.d.ts`. Editing `src/shared/types.ts` for them does nothing.
- `src/env.d.ts` owns `ImportMetaEnv` (the `VITE_*` keys) and `declare const __SENTRY_RELEASE__`. It is incomplete: `VITE_SENTRY_DSN` is read in `src/main/index.ts` and listed in `.env.example` but is missing from the interface.

To add a channel:
1. Register inside the matching setup function in `src/main/ipc/` — `games.ts`, `installer.ts`, `likes.ts`, `tg-news.ts`, `feedback-replies.ts`, `plugin-host.ts` (`plugin-host:*`, `millennium:*`, `decky:*` and the Steam bridge channels `restart-steam`, `get-steam-bridge-status`, `recheck-steam-bridge`, `set-steam-cef-debugging`), `window-controls.ts` (that one exports `setupWindowControls`, not `…Handlers`, and is a grab-bag: `show-system-notification`, `clear-cache-only`, `clear-all-data-and-restart`, `logger:log` and `logger:open-logs-folder` live there too — look there before adding a logging, cache-clearing or notification channel; main-process code shows a notification through `showSystemNotification()` in `src/main/utils/system-notification.ts`). Handlers also live outside `ipc/`: `src/main/window.ts` (`liquid-glass:*`, registered at module import time), `src/main/utils/store-storage.ts`, `src/main/auto-updater.ts`, `src/main/changelog.ts`, `src/main/index.ts`.
2. Call the setup function from `src/main/index.ts`, next to the other `setup*Handlers()` calls. Nothing is auto-discovered.
3. Add the method to `ElectronAPI` in `src/shared/types.ts`, **or** to `src/window.d.ts` for the other five bridges.
4. Wire it in `src/preload/index.ts`.

**Push-event bridges own their teardown.** All 26 `on*` methods in `src/preload/index.ts` return `() => ipcRenderer.removeListener(channel, handler)`; give a new listener the same disposer in both the preload impl and its `ElectronAPI` / `window.d.ts` type (`(cb) => () => void`), and call it from effect cleanup — returning `void` compiles and leaks a listener on every remount, and `removeAllListeners` would kill other subscribers of the same channel. `windowControls.onMaximizedChange` is the one whose `src/window.d.ts` type still says `=> void`, so its disposer is invisible to callers.

**Handlers never throw across the boundary.** Return `{ success, error }` — custom Error properties do not survive IPC. `src/main/ipc/installer.ts` maps `ManualSelectionError` / `RateLimitError` / `NetworkError` (all from `src/main/installer/errors.ts`) into `needsManualSelection` / `isRateLimit` / `isNetworkError` booleans. Read-only handlers return `null`/`[]` instead.

Window channels are colon-separated: `window:minimize` (which **hides to tray** — the tray is the only way back), `window:maximize`, `window:close`, `window:is-visible`. Maximize state is pushed as the `window:maximized` event from `src/main/window.ts`; there is no `window-is-maximized` handler.

## Database and sync

`src/main/db/database.ts` is a synchronous better-sqlite3 singleton on the main thread. Get the handle with `getDatabase()` — `DatabaseManager` is not exported and has no `.prepare`.

- **The worker thread does WRITES ONLY**: `upsertGames`, `deleteGame`, `deleteGames`, consumed solely by `src/main/db/sync-manager.ts`. Every read, FTS5 search and spellfix fallback runs synchronously on the main thread: `GamesRepository`, plus `deep-link-game.ts` (`findDeepLinkGameId`) and `recommendations-source.ts`.
- `src/main/db/db-worker-client.ts` resolves the worker at `process.resourcesPath/app.asar/out/main/db-worker.js` when packaged. Nothing type-checks that string — renaming the rollup entry breaks sync at runtime only.
- **Migrations are name-keyed, not versioned.** `src/main/db/migrations.ts` replays the entire array on every start with no `user_version` and no applied-migrations table. Every migration must self-check: column adds via `addColumnIfMissing()`, one-shot data work via a marker row in `sync_metadata` (`forceResyncOnce()`). `runMigrations()` rethrows, so a throw propagates out of the `DatabaseManager` constructor.
- **Migrations never run on a fresh DB.** `database.ts` calls `createTables()` and returns; `runMigrations()` is only reached for a pre-existing DB that already has a `games` table. Anything that must also hold for first launch has to be duplicated into `createTables()`.
- **Adding a `games` column is a five-place lockstep change**: the DDL in `createTables()`, an `addColumnIfMissing` migration, `gameToInsertParams()`, the `SYNCED_COLUMNS` array (both in `src/main/db/db-queries.ts`), and usually a `forceResyncOnce` migration. The `_assertNever<…>()` guards in `db-queries.ts` make `pnpm type-check` fail if steps 3/4 diverge; steps 1/2/5 fail silently at runtime.
- `UPSERT_GAME_SQL` uses `ON CONFLICT(id) DO UPDATE` built from `SYNCED_COLUMNS` specifically so `user_unlocked` (local-only, how a user reveals a `hide = 1` translation) survives sync. Any new local-only column must stay out of `SYNCED_COLUMNS`; never switch to `INSERT OR REPLACE`. The counters (`likes`, `downloads`, `subscriptions`) are written on insert but skipped on conflict (`COUNTER_COLUMNS`): after insert only `src/main/db/game-counters.ts` updates them, so a games page fetched before a counters broadcast cannot roll them back.
- **Every query that lists games must use `VISIBLE_GAMES_SQL`** (`db-queries.ts`) or it leaks hidden translations. It is `approved = 1 AND (hide = 0 OR user_unlocked = 1)`, relaxing to `approved = 1` when `IS_ADMIN_BUILD` (`src/shared/admin-mode.ts`, from `VITE_ADMIN_MODE`, set only by `.github/workflows/tg-build.yml`).
- Search: FTS5 for queries ≥ 2 chars, `name LIKE ?` for 1 char (and as fallback when tokenization yields nothing), spellfix fallback only when the query returned zero rows and `isSpellfixAvailable()`. The dictionary table is `spellfix_words` (a flat list of the ≥3-char words of `name`, no transliterated forms) and is fully rebuilt on every batch upsert. `games_fts` is `fts5(game_id UNINDEXED, name_search, search_keywords, tokenize='unicode61')`, maintained by manual delete+insert. Cross-script matching (Cyrillic query → Latin title and back) comes from transliteration, not spellfix: `generateSearchableString()` in `src/shared/search-utils.ts` stores lowercased `name` plus its `cyrillic-to-translit-js` transliteration plus an apostrophe-stripped variant into the derived `name_search` column at upsert time, and `buildFtsQuery()` transliterates the query the same way. `name_search` is written, never computed at read time — changing the search helpers needs a reindex migration over existing rows (see `reindex_fts_without_apostrophes`), not just a redeploy.
- `SyncManager.getInstance().sync(...)` does a full sync when the games table is empty or no `last_sync_timestamp` exists, otherwise a delta, falling back to full on delta failure. There is no staleness window.
- **Sync is cursor-based end to end.** Each cursor is the server's own newest timestamp among the rows received, never the local clock: `last_sync_timestamp` (games `updated_at`), `deleted_games_synced_at` (`deleted_at`), `tag_names_synced_at`, `game_counters_synced_at` (`touched_at`). Games and deletions are read rewound one minute (`rewind()` in `src/main/db/sync-cursor.ts`) to catch rows committed late, which is safe because every apply is idempotent; tag names are not, since one bulk write gives them all the same timestamp. Pages are keyset, never `.range()` offsets: order by the cursor column plus a unique tie-breaker and continue with `afterCursor()`, since an offset shifts when rows change mid-run and silently skips one.
- **A new delta + realtime feed goes through `createDeltaStream()`** (`src/main/db/delta-stream.ts`): `fetchSince` yields batches and the watermark is saved only on batches that carry one, broadcasts are zod-checked, overlapping catch-ups fold into one extra pass, and a resubscribe catches up. `game-counters.ts` and `feedback-replies.ts` are the two users.
- **Likes**: `src/main/likes.ts` owns `my_likes(game_id, liked, server_liked)`. A row with `liked != server_liked` is unsent. The shown count is the server count plus that unsent toggle (`likesWithUnsentSql()`, also used by `game-counters.ts`). Clicks are debounced per game (400 ms) and sent one at a time through the `track` edge function. A toggle folded back to `server_liked` is never sent. 4xx reverts to `server_liked`, network/5xx retries after 60 s. `syncLikes()` on startup takes the server's `liked_games` list, except for unsent rows. The renderer mirrors the liked set through `src/renderer/store/likesBridge.ts`; `initLikes()` runs once in `main.tsx` beside `initFeedbackReplies()`, outside React — IPC-to-store bridges go there, not into hooks in `App.tsx`.
- Server-side deletions of games whose translation is still installed are **tombstoned** into `pending_game_deletions` in `sync_metadata` and cleared later by `processPendingDeletions()`.
- Realtime is broadcast-channel based (`src/main/db/supabase-realtime.ts`), not `postgres_changes`; `subscribe()` takes an **array** of `BroadcastSubscription` objects.
- **Clearing the catalog DB is two-phase and restart-based**: `clear-cache-only` / `clear-all-data-and-restart` call `closeDatabase()` → `deleteDatabaseFile()` → `app.relaunch()`. `deleteDatabaseFile()` unlinks `lbk.db`/`-wal`/`-shm` eagerly and, if an unlink fails (Windows keeps WAL files locked), writes a `lbk.db.delete` marker in userData that the `DatabaseManager` constructor consumes on the next launch. Never unlink the DB files directly — go through `deleteDatabaseFile()`.

## Installer

Orchestrator is `src/main/installer.ts` (there is no `src/main/installer/index.ts`). Order: platform compatibility → resolve gamePath (custom paths blocked for `license_only`) → `resolveGameBuildOs()` → stage into `<gamePath>/.lbk-temp` → disk check for 2× archive size → download+extract → optional backup → copy → cleanup → `saveInstallationInfo` → `applySteamIntegration`.

- **Archive variant priority**, identical in the disk-space step and the download step and must stay in sync: build-OS variant (`steam_linux_*` / `steam_mac_*`) → store-specific (`epic/gog/xbox/uplay/ea_*`) → `archive_path`. `resolveGameBuildOs` (`src/main/utils/game-build.ts`) sniffs ELF/Mach-O magic on disk, then Steam's compat tool, then host OS — the host OS is *not* the build OS for Linux Steam titles under Proton.
- **There is no macOS installer column** — only `installation_file_windows_path` and `installation_file_linux_path` exist. macOS falls back to the Linux path and runs it directly after `chmod +x`; `checkPlatformCompatibility()` (`src/main/installer/platform.ts`) blocks a translation on macOS when only the Windows installer exists.
- Install metadata is written **twice**: `.lbk-translation.json` in the game folder and a mirror at `userData/installation-cache/<gameId>.json`. The userData directory is the source of truth for "what is installed" (`getAllInstalledGameIds()` reads filenames). `src/main/installation-watcher.ts` fs.watches it with a 100 ms debounce; `checkInstallation()` rewrites the cache only when fields actually changed, to avoid a watcher feedback loop.
- Backups go into a hidden `.lbk-backup/` dir at the game root and are only written if absent, so re-installing never overwrites the pristine original. Restore tries `.lbk-backup/<rel>`, then legacy `<file>_backup`, then `<file>.kbak`. `findBackupDir()` / `findInstallationInfoFile()` **rename** legacy `.littlebit-*` paths as a side effect.
- Translations shipping an executable installer return early through a `installer:confirm-run` → `installer:run-decision` round trip. If the renderer never calls `respondRunInstaller(gameId, …)` the main-process promise hangs forever. That path also returns before the backup/copy branch — it records `installedFiles: []`, `components.text.files: []` and `hasBackup: false`, so no backup exists and uninstall relies entirely on the shipped uninstaller (`installInfo.installerPath`); backup restore is a no-op for installer-based translations and the manual-cleanup fallback has nothing to delete.
- `runProton()` **renames the installer file on disk** to a transliterated name (`renameFileToTranslit`, cyrillic-to-translit-js 'uk' preset) before launching it, so a Cyrillic installer path stored earlier is stale afterwards. `runUninstaller()` and `rerunInstaller()` retry via `getTransliteratedPath(storedPath)` when the recorded path no longer exists — keep that fallback in any new code that re-opens a saved installer path.
- `applySteamIntegration` (`src/main/installer/steam-integration.ts`) is the shared tail for both paths — steps appended after the normal flow were silently skipped for installer-based translations.
- **Achievements never go into `appcache/stats`** — Steam compares the schema's SHA1 with the server and replaces a modified `UserGameStatsSchema_*.bin`. The installer parses the archive's schemas (`prepareAchievements()` in `src/main/achievements/install.ts`; `binarykvparser`, pinned to 2.2.0 because 2.3.0 was published without its bundled `long`; `utils/achievement-strings.ts`) into `userData/achievement-strings/<appid>.json` (`achievements/strings-store.ts`) and records `components.achievements = { files: [], appIds, archiveHash }`; `syncAchievementsToPlugin()` (`src/main/achievements.ts`) aggregates them into the LBK Bridge plugin's `achievements.json` through `writeBridgePluginData()` (Millennium plugin dir and Decky data dir), so translated achievements reach Steam **only through the plugin** (Millennium v3 or Decky). `InstallResult.achievementsDelivery` says which case applies; the install-success modal offers «Перезапустити Steam зараз» only for `plugin-next-start`, and for `plugin-live` while a newer LBK Bridge waits for Steam's next start (`updateAfterRestart`, see Renderer). Re-install is skipped only when `archiveHash` matches **and** this game's strings files exist (`isAchievementsComponentCurrent()`; `hasAchievementStrings([])` is `false`). Records with non-empty `files` are legacy `.bin` copies (v2.0–v2.23.1): at startup `migrateLegacyAchievements()` (`achievements/legacy.ts`) restores each `_backup` or deletes the file and marks the component not installed (`{ installed: false, files: [] }`, both record copies via `rewriteInstallationRecord()` in `installer/installation-info.ts`), so the install dialog offers achievements again — nothing is re-downloaded. The three install endings (achievements only, shipped installer, copied files) share `finishInstall()` in `src/main/installer.ts`. Strings go with their record: `'install-record-removed'` on `appEvents` (emitted by `installer/cache.ts`, handled in `startAchievements()`) covers records dropped outside the uninstall flow, and startup removes strings without a record. Saving them (`commitAchievementStrings()`) runs after the game files are copied, so a failure only drops the achievements component, never the install.
- Downloads go through the Supabase Edge Function `get-download-url` (invoked by `getSignedDownloadUrl()` in `src/main/tracking.ts`) that enforces rate limits. Writes to `<output>.part`; a `NetworkError` **preserves** the `.part` for resume, 404/cancel deletes it. Pause aborts with reason `'PAUSED'`, persists to `userData/paused-downloads/`, and throws `PausedSignal` at the IPC boundary so the renderer sees `{ success: false, paused: true }`. Resume refreshes the signed URL after 55 minutes.

## Game detection and Steam

`src/main/game-detector/` has ten modules: `steam`, `gog`, `epic`, `xbox`, `uplay`, `ea`, `rockstar`, plus `heroic`/`lutris` (Linux helpers behind GOG and Epic) and `kurin` (a separate catalog source via `syncKurinGames()`, not a path detector). `detectGamePath(installPath, steamAppId?)` switches on the seven store types and returns `exists: false` for `emulator` and `other`. GOG and Epic resolve on Linux via Heroic/Lutris; Epic also reads native EGLv2 installations from `~/.local/share/com.epicgames.eglv2/installations.jsonl`.

- Steam resolution is **app-id-first** via `appmanifest_<appid>.acf`; the installdir map is only a fallback (Steam suffixes duplicate installdirs with the app id). Always pass `steamAppId` — omitting it silently degrades to ambiguous folder-name lookup. `getSteamLibraryAppIds()` is async.
- The «Доступно з GOG» / «Доступно з Epic» filters match the store library's **titles** against catalog `name` with `name COLLATE NOCASE IN (...)` — exact, no fuzzy matching. `getCleanTitle()` (`src/main/game-detector/game-titles.ts`) is a hand-written alias table (catalog title → store title variants, looked up in reverse) applied in `gog.ts`, `epic.ts` and `lutris.ts` before the titles cross IPC. Native EGLv2 Epic installs also join the Epic filter by their recorded install paths, since `installations.jsonl` has artifact IDs but no display titles. For title-based store sources, a game whose store title differs (edition suffix, ™) stays invisible until it gets an entry in the alias table — fix it there, not with fuzzy matching in the renderer.
- `src/main/steam-watcher.ts` watches `libraryfolders.vdf`, the `steamapps` dirs and `licensecache` with a 2 s debounce (`DEBOUNCE`).
- Steam bridge (`src/main/utils/steam-bridge.ts`): `getSteamBridge()` / `ensureSteamBridge()` hand out a transport that runs only the named ops of `createOps()` (`packages/lbk-bridge-core/src/ops.ts`, shipped to CDP as `STEAM_OPS_SOURCE` in `src/main/utils/steam-bridge-ops.ts`) — never arbitrary eval. The **plugin** transport is used when the LBK Bridge Millennium plugin is connected, otherwise **CDP** (`steam-cef.ts`) against `SharedJSContext` on a discovered port (8080 first; the User-Agent must contain `Valve Steam Client`). The port opens only if `.cef-enable-remote-debugging` exists in Steam's working directory **and** Steam restarted since. On macOS that directory is `Steam.AppBundle/Steam/Contents/MacOS` (`MACOS_APP_BUNDLE_SUBPATH` in `src/main/utils/cef-flag-file.ts`), not the data root. Millennium on Windows/Linux deletes that file and closes TCP CDP (`detectMillennium().blocksTcpCdp`) — from the second Steam start on: the first session after activation still has the port, because the file is deleted only after steamwebhelper started — so the flag file is left alone there and Millennium v3 gets the plugin instead. The macOS fork adds `--remote-debugging-pipe`, keeps TCP CDP open next to the pipe, and deletes the flag file about 1 s into every wrapper start (verified live on lbk.4); LBK recreates it whenever the plugin connects (`restoreCefFlagFileAfterMillennium()` on `plugin-connection`), so Steam started later from the Dock still has CDP; `blocksTcpCdp` stays `false` there and `runVerify` switches to plugin-only waiting when it sees a pipe with Millennium v3 (`nextVerifyStep()`). Never remove the flag file while Decky Loader is installed (`isDeckyInstalledSync()`): Decky creates it only in its installer. Launch options, workshop, collections, the self-shortcut, artwork and library app ids all go through the bridge and must handle every `SteamBridgeFailure` (`cef-unavailable`, `steam-not-running`, `cef-blocked`, `millennium-plugin-pending`, `millennium-outdated`).
- **Restarting Steam goes through `restartSteamOrchestrated()`** (`src/main/steam-restart.ts`): it never launches Steam after a failed `shutdownSteam()` (elevated Steam, gamescope, timeout) and runs queued actions in the gap. It refuses to shut Steam down while `RunningAppID` names a Steam game (`getRunningSteamGameId()`: HKCU on Windows; Linux and macOS Steam never write the key to `registry.vdf`, so Linux reads the `reaper SteamLaunch AppId=<id>` process every game runs under and macOS the `SteamGameId=` every game process inherits (`ps -E`); reason `game-running`), and a forced kill takes only `steam.exe` by PID — never `taskkill /T`, which would take the game, or LBK started from its Steam shortcut, with it. Concurrent restarts share one run (`p-memoize`, constant `cacheKey`), so nothing reachable from `orchestrate()` may call `restartSteamOrchestrated()` — it would wait on itself; a caller that joins a run started without `verifyBridge` verifies the bridge itself. The restart prompt fires only from the Settings toggle, at most once per bridge fingerprint (`claimSteamRestartPrompt()`); a verified failure persists as `steam-bridge-verdict` and stops all further prompts until «Перевірити ще раз». The bridge is three modules: `utils/steam-bridge.ts` (transports, `getSteamBridge()` / `ensureSteamBridge()`, status), `utils/steam-bridge-verdict.ts` (fingerprint, verdict and prompt store keys) and `utils/steam-bridge-lifecycle.ts` (`verifyBridgeAfterLaunch()`, `startSteamBridge()` and its `appEvents` listeners).
- **LBK Bridge plugins are TypeScript workspace packages** (`pnpm-workspace.yaml` `packages: [packages/*]`), built by `pnpm build:bridge` (part of `prebuild`) into gitignored output and never committed. `packages/lbk-bridge-core` (`@lbk/bridge-core`, a root **devDependency** so electron-vite bundles it into main; keep it out of `dependencies`, `bundled-dependencies.test.ts` checks) holds `contract.ts` (op `{ args, result }` interfaces, `SHARED_STEAM_OPS` / `PLUGIN_ONLY_OPS`, `BRIDGE_VERSION`, `BRIDGE_PLUGIN_NAME`, `BRIDGE_PROTOCOL`, `BRIDGE_WS_PATH`, `BRIDGE_HOSTS`; main and `src/main/steam-bridge-server/` import them straight from `@lbk/bridge-core/contract`, never a local copy), `ops.ts` (`createOps()`, arg validators on ts-belt's `G` guards), `protocol.ts` (zod/mini for bridge.json and the WS frames, and the handshake HMAC; zod/mini never compiles validators, so Steam's CSP does not matter, and `bridge-artifacts.test.ts` fails on any `Function`/`eval` in a bundle; never call `z.config()`: it writes a `globalThis` object that every zod copy in SharedJSContext shares), `achievements.ts` and `bridge.ts` (`createBridge({ host, dataBase, env })`, all state in the closure; `bridge.events` is a plain `EventTarget` that dispatches `change` whenever status, idle, connectedAt or lastError actually changes and `achievements` whenever `achievementApps()` (the apps with strings in the Steam UI hook's last `achievements.json` read) does, never after `disposed`, and the Decky status line reads it through `useSyncExternalStore`, so the artifact sandbox also gets `EventTarget` and `Event`). The ops reach CDP as an esbuild IIFE (`dist/steam-ops.iife.js`) imported with `?raw`; ESLint lets `ops*.ts` import only siblings and `G` from `@mobily/ts-belt` (esbuild keeps a whole ts-belt namespace, `A` alone is ~45 KB; no zod: the whole bundle goes with every CDP call, `steam-bridge-ops.test.ts` has a size budget). ## Platform branches

Use the helpers in `src/main/utils/platform.ts` (`isWindows` / `isLinux` / `isMacOS` / `getPlatform` / `isPortable` / `forCurrentOS`), not bare `process.platform`. `getPlatform()` can return `'unknown'`, which is why `forCurrentOS` uses an `in` check rather than truthiness.

- **Windows**: read the registry through `registry-js` (`enumerateKeysSafe`, plus `getRegistryString()` in `src/main/utils/registry.ts` for one value), never by spawning `reg.exe`: `reg query` stdout comes through the OEM code page, which has no «І», so Cyrillic install paths would not survive it. The native module is built on install (`allowBuilds` in `pnpm-workspace.yaml`) and is a no-op off Windows. Build `dist:win` only on Windows: off Windows the install leaves a host-OS stub `registry.node`, `npmRebuild: false` packs it as is, and the app crashes on start.
- **Linux/Steam Deck**: `src/main/index.ts` appends Chromium switches (`no-sandbox`, `disable-gpu-sandbox`, `enable-gamepad-extensions`, `VaapiVideoDecoder`, `ignore-gpu-blocklist`) and deletes `GTK_IM_MODULE` / `QT_IM_MODULE` in a top-level `if (isLinux())` block that sits **above the bulk of the imports** and long before `app.whenReady()` — moving it later silently breaks Gaming Mode. `runProton({ protonPath, filePath, args })` prefers the bundled `resources/umu/umu-run`; the installer window renders in Game Mode only with gamescope plus `STEAM_MULTIPLE_XWAYLANDS=1` and `PROTON_VERB=waitforexitandrun`. Extraction prefers a system 7z. Started from a Steam shortcut or in Game Mode, LBK inherits the overlay's `LD_PRELOAD`: every child it starts goes through `getCleanEnv()` (`src/main/utils/host-exec.ts`; used by `spawnOnHost`/`execFileOnHost`, 7z, native installers and the Decky installer) — except `runProton()`, which passes the environment through on purpose because umu clears `LD_PRELOAD` itself under gamescope.
- **The Proton prefix is a throwaway**: `~/lbk-proton-prefixes/<sanitized translit installer basename>`, `rmSync`'d ~1 s after the installer exits. A `steamapps/compatdata/<appId>` prefix is reused and kept only when an appmanifest resolves from the *Proton build's* own folder (`findSteamAppId(dirname(protonPath))`) and that compatdata dir already exists — so assume nothing written into the prefix survives.
- **Flatpak sandbox**: on Linux the app may run inside one, so anything launching an external process (Steam, Heroic, Lutris, host `flatpak`) must route through `flatpak-spawn --host`. The helpers live in `src/main/utils/host-exec.ts`: `isFlatpak()`, `execFileOnHost()` (buffered output, timeout) and `spawnOnHost()` (detached and unref'd; `flatpak-spawn` drops the sandbox env, so its `env` is passed as `--env=K=V`), plus `system32()` for Windows tool paths. A bare `spawn('steam', …)` silently fails for every Flatpak/Steam Deck user.
- **macOS**: builds are **per-arch dmg + zip for x64 and arm64 — not a universal binary**. Liquid Glass is gated on Darwin ≥ 25 (macOS 26). Installs must run `resignMacBundles()` (`src/main/installer/mac-codesign.ts`): replacing `Contents/MacOS/*` or `Info.plist` makes the kernel SIGKILL the game, so the bundle is `xattr -cr`'d and ad-hoc signed with `--preserve-metadata=entitlements,flags` and deliberately **not** `--deep`. A signing failure sets `hasInstallError: true` rather than failing the install.
- **Open http(s) links through `openExternalUrl()`** (`src/main/utils/open-external.ts`), never `shell.openExternal` directly: on Linux it resolves the browser itself (xdg-settings → Flatpak → native binary, cached) because SteamOS's xdg-open hands the URL to the Discover store. It also rejects `file:`/`javascript:`/`data:`/`vbscript:` and returns `{ success, error }` rather than throwing. Bare `shell.openExternal` is reserved for launcher protocol URLs (`epic://`, `uplay://`, `steam://`).

## Renderer

State is split three ways and the split is intentional.

- **12 Zustand stores** in `src/renderer/store/`. The five with middleware (`useSettingsStore`, `useSubscriptionsStore`, `useWorkshopInstallsStore`, `usePromoModalStore`, `useChangelogStore`) use the curried `create<Interface>()(...)` form; the plain seven use `create<Interface>((set, get) => ...)`. Colocate actions, and read across stores with `OtherStore.getState()`, never a hook.
- **React Query** covers read-only fetches: the catalog queries in `src/renderer/queries/`, the Sidebar's `['teams']` / `['tag-options']`, `useFacetData`'s `['facet-rows']` / `['library-memberships']` / `['installed-translation-ids']`, and the network reads (`useNewsFeed`, GamePage's `['game-banners', id, slug]`). **Any hook reading the local SQLite catalog must go through `useSyncAwareQuery`** (`src/renderer/queries/useSyncAwareQuery.ts`), which forces `enabled: syncStatus === 'ready' || 'error'`. Skipping it caches an empty result for the 5-minute default `staleTime` during the Supabase sync. Non-React-Query hooks hand-roll the same guard (`useDeepLink.ts` waits on `useStore.subscribe`). Catalog-derived queries go stale through IPC push events: their owner subscribes and calls `queryClient.invalidateQueries` after a 300 ms debounce. The `useFacetData` keys are purely event-driven (game, install, library and Workshop events, `staleTime: Infinity`, an idle prewarm and `structuralSharing: false` on the rows, whose identity `useFacetCounts` watches); the Sidebar keys invalidate on `onGameUpdated` but keep the 5-minute default `staleTime`, so a Sidebar remount after that (e.g. a gamepad-mode toggle) also refetches. Banners use `staleTime: Infinity` and a short 5-minute `gcTime` because the server caps impressions per `machine_id`, so a later visit asks again.
- Deep links (`lbk://games/{slug}/{team}`) resolve in main through `find-deep-link-game-id` (`src/main/db/deep-link-game.ts`: one `VISIBLE_GAMES_SQL` query by slug-or-id, team matched in JS because SQLite's `lower()` folds ASCII only); never load the whole catalog in the renderer to look one game up.
- `src/renderer/hooks/useGames.ts` is **not** React Query — it is hand-rolled `useState` + `AbortController` + four IPC listeners (`onGameUpdated`, `onGameRemoved`, `onInstalledGamesChanged`, `onSteamLibraryChanged`) that patch the list in place. Status and author filters run in SQL; content-type filters (`with-achievements`, `with-voice`, `from-workshop`) are AND-combined client-side. A new filter type needs both the SQL path **and** `matchesContentTypes`, or realtime rows bypass it. It does no debouncing of its own and fires an IPC/SQLite query per prop change — the 300 ms debounce lives in its single caller (`useDebounce(searchQuery, 300)` in `Sidebar.tsx`), so a second search entry point wired straight to `useStore.searchQuery` would run an FTS5 query per keystroke.
- **Millennium / Decky setup UI** is one modal, `components/Modal/SteamPluginSetup/SteamPluginSetupModal.tsx`, opened only through `useSteamPluginSetupStore.openSetup(variant, source)` and mounted in `MainLayout` after `GlobalModal` (so it stacks on top; the install-success action closes the global modal rather than `keepOpen`). It captures Escape at `window` (`SetupFrame`) so the dialog underneath does not close with it. Each flow is an xstate machine next to it (`millenniumInstallMachine.ts`, `millenniumUninstallMachine.ts`, `deckySetupMachine.ts`) run with `useMachine(machine.provide(…))`: the machine files touch `window.electronAPI` only inside their default actors, so node tests import them and swap the actors, and the flow component provides the actors that drive a `useActionPhase` button (its `run()` wraps the IPC call). The flow sends the plugin-host state in as `HOST_STATE` (the Decky machine is also seeded with the stored state through `input`, so its `always` guards see it on the first render); the Decky flow finishes on that pushed state (main's Decky watcher), never on a poll. Steps are view builders in `SteamPluginSetup/steps/` (`millenniumIntroView()`, `restartChoiceView()`, `resultView()`, …) that return a `SetupView` (title, dismissable, body, footer), and each flow renders exactly one `<SetupFrame view={…}>` — a step that rendered its own frame would remount the `Modal` and replay its open animation on every transition. Millennium copy and decisions (`failureStep()`, `introMode()`, `isPluginConnected()`, `RestartChoice`) live in `millenniumSetup.ts`. Offers are contextual only — the install-options note + badge, the install-success modal, Settings — never at startup, and only while `steamCefDebuggingEnabled` is on; all four read one model, `utils/pluginHostOffer.ts` (`millenniumOffer()`, `deckyOffer()`, `deliveryNote()`, `successOffer()`, the `OFFER_ACTIONS` labels), and open targets through `openOfferTarget()`; the Settings rows are `pluginHostEntries()`. A Millennium plugin update waits for Steam's next start (a Decky plugin reloads on install), so `SteamBridgeStatus.millennium.plugin.updateAfterRestart` (main's `pluginUpdateAfterRestart()`: the hello version of the connected Millennium plugin older than its installed `plugin.json`, and no Millennium removal queued) adds a row and `OFFER_ACTIONS.restartSteam` (target `steam-restart`) to `pluginHostEntries(host, status)`, and a line plus «Перезапустити Steam зараз» to the install-success modal of `plugin-live` achievements; it never prompts by itself. «Більше не пропонувати» sets `millenniumOfferDeclined` / `deckyPluginOfferDeclined` in `lbk-settings`; the install-success modal checks them, Settings (`source: 'settings'`) and the install-options note ignore them. In `InstallOptionsDialog` the achievements checkbox (`InstallOptions/AchievementsOption.tsx`) is locked until the badge is ready (`millennium`, `decky`, `after-restart`; `achievementsOptionState()` in `utils/installOptions.ts`), with the install button right under it; it unlocks by itself on `steam-bridge-status-changed`. A locked box sends the installed state, not `false` — `false` makes the installer delete installed achievement strings. The achievements badge (`ui/AchievementsDeliveryBadge.tsx`) only renders `SteamBridgeStatus.achievements`. That status lives in `useSteamBridgeStatusStore` and the plugin-host state in `useSteamPluginHostStore`, both kept current by `useSteamBridgeStatusSync()` (called from `App.tsx`: push events plus one idle fetch), so `useSteamBridgeStatus(enabled)` / `useSteamPluginHost(enabled)` return the last known value at once and only revalidate when `enabled` turns on — do not move them back into per-component state, the badge then flashes «Перевірка…» on every open. The install-success copy and actions are `installSuccessMessage()` / `installSuccessActions()` (`utils/installSuccess.ts`), with the bridge status fetched once through the store. `data-gamepad-skip` *removes* an element from modal navigation — do not put it on a button the user should reach.
- **"Is a translation installed" is dual-sourced** — file installs in `useStore.installedTranslations` and Workshop subscriptions in `useWorkshopInstallsStore`. Always read through `src/renderer/hooks/useInstalledTranslations.ts`; reading `useStore.installedTranslations` directly misreports every Workshop translation as not installed.
- Persistence goes through electron-store, never `localStorage` (an ESLint **error** via `no-restricted-globals`). The one exception is the one-time `localStorage` → electron-store migration that runs at module import time in `src/renderer/store/electronStorage.ts` (keys `lbk-settings`, `subscriptions-storage`, `has-launched-before`, guarded by `__migration-v1-done`) — the tree's only `no-restricted-globals` disable; do not "clean it up", it must keep running before any store's `getItem` or every pre-migration user silently loses settings and subscriptions on upgrade. `electronStorage.ts` `getItem` is deliberately synchronous (`sendSync`) so rehydration has no flash of defaults. `useSubscriptionsStore` keeps the newest 200 `notifications` (recounting `unreadCount` after the trim) and 500 `seenFeedbackReplyIds`; the replies catch-up is watermark-based, so the id list only has to cover the live/catch-up overlap. Only `subscriptions-storage` has a Map/Set-serializing storage; adding a `Set` or `Map` to `lbk-settings`, `promo-modal-storage` or `workshop-installs-storage` persists as `{}`. The LBK Bridge core (`packages/lbk-bridge-core`) is the other place that uses `localStorage`: Steam's own, in SharedJSContext, reached through `env.steam` (`steam-globals.ts`) to remember spent secrets, because a plugin has no electron-store; it never touches the bare global, so it needs no disable.
- `useSettingsStore` force-disables `animationsEnabled` and `liquidGlassEnabled` on weak hardware (`cpuCount <= 4 || totalRamGB <= 8`) on every rehydrate, and `toggleAnimations()` / `toggleLiquidGlass()` additionally return without setting state when `isHardwareWeak` — flipping either flag on such a machine is a silent no-op, not just an override. `isHardwareWeak` is computed once at module load (`electronAPI.getSystemInfo()`, falling back to `navigator.hardwareConcurrency <= 4`) and exported from `useSettingsStore.ts`; gate UI on it instead of re-detecting hardware in a component. Animations are gated globally by `MotionConfig` in `MainLayout.tsx` plus a `.no-animations` class in `globals.css`, not per component.
- **Gamepad navigation is a DOM-attribute contract**, driven by `document.querySelector` in `useGamepadModeNavigation.ts`. New interactive UI is unreachable on Steam Deck unless it opts in with `data-gamepad-card`, `data-gamepad-action`, `data-gamepad-primary-action`, `data-gamepad-index`, `data-gamepad-dropdown[-item]`, `data-gamepad-confirm` / `-cancel` / `-skip`, `data-gamepad-header-item`, `data-gamepad-modal-item`, or `role="dialog"`. There is no central registry.
- Virtualizer sizing constants live once in `src/renderer/components/Sidebar/constants.ts` (`GAMEPAD_CARD_STRIDE = 156`, `GAME_LIST_ROW_ESTIMATE = 84`) and are shared by the game lists and gamepad scroll math. Changing a card's Tailwind size without updating the constant desyncs focus.
- **i18n is i18next, Ukrainian only.** The whole dictionary is one file, `packages/lbk-i18n/src/uk.ts` (workspace package `@lbk/i18n`, a root devDependency bundled like `@lbk/bridge-core`), `as const`, grouped by UI area (`tray.open`, `steamRestart.failed`, `installOptions.*`, `settings.<block>.*`), never by code module. `src/shared/i18n/i18n.ts` holds the one instance for main and renderer (`t`, `i18n`; initialised synchronously at import, `escapeValue: false`), typed through i18next's `CustomTypeOptions`, so a wrong key or interpolation name fails `pnpm type-check`; import `t` from `@/shared/i18n/i18n` in both processes. Call `t('…')` where the text is used — no constants that only hold a `t()` result — and when a closed union maps onto dictionary keys, name the keys after the members and write `` t(`millennium.failure.${reason}`) `` instead of a `Record` of `t()` calls (TypeScript checks every member has a key). Plurals are `_one`/`_few`/`_many`/`_other` keys with `count` (`_other` = the `few` form), variants are i18next `context` keys (`runDeclined_installer` / `_script`), never a word glued from parts; a sentence with inline markup uses `Trans` from `react-i18next` (the renderer root has `I18nextProvider`). The LBK Bridge packages read `uk` directly (`uk.deckyPlugin.*`): i18next contains the word `Function`, which `bridge-artifacts.test.ts` rejects, and the CDP ops take user-visible text as arguments (`syncCollection`'s `name` comes from main's `t('steamCollection.name')`). Every user-visible string lives there, and `no-restricted-syntax` in `eslint.config.mjs` fails `pnpm lint` on any Cyrillic string, template or JSX text outside it. Exempt are tests, fixtures, `e2e/` and the files that match Ukrainian catalog data (`game-titles.ts`, `specialTranslators.ts`); a single matching literal elsewhere gets `eslint-disable-next-line no-restricted-syntax -- <what it matches>` (Kurin's team in `kurin.ts`, the installer-name checks in `platform.ts`); regex literals are not checked. Changing a dictionary value can break e2e, which selects on the text.
- Colours come from CSS variables via `bg-glass` / `bg-bg-dark` / `text-color-main` / `text-color-accent`, not `gray-*` or `cyan-*`. Tailwind 4 has no `tailwind.config.js`: tokens live in the `@theme inline` block at the top of `src/renderer/styles/globals.css` — plain `var()` forms under `--background-color-*` / `--text-color-*` / `--border-color-*` (`bg-`, `from-`/`via-`/`to-` resolve against `--background-color-*` first), RGB-triplet forms under `--color-*` (`rgb(var(--x-rgb))`) for every other utility. `/NN` works on all of them via `color-mix`. Element resets and the `.no-animations` killer sit in `@layer base` — unlayered CSS beats every utility in v4.

- `src/renderer/components/ui/MarkdownText.tsx` allows exactly 8 tags (`p`, `strong`, `em`, `ul`, `ol`, `li`, `br`, `code`) and rewrites headings to `<p>`. Widening the allowlist changes the trust boundary for Supabase-sourced text.

## Conventions

- **Named exports.** Components are `export const Name: React.FC<Props>` with a local non-exported `interface NameProps`. The only default exports in the tree are `src/renderer/components/MainContent/Gallery.tsx` and the three plugin entries their toolchains require (`packages/lbk-bridge-decky/src/index.tsx`, `packages/lbk-bridge-millennium/frontend/index.tsx`, `packages/lbk-bridge-millennium/webkit/index.tsx` — ttc's webkit wrapper calls only the default export, so a named one still builds and does nothing in Steam). No re-exports and no barrel files: import every symbol from the module that defines it (`@/main/game-detector/store-cache`, `shared/types`, …), and remember knip fails the build on an export nobody imports.
- Hooks and stores: one `use*` export per file, file named after the export.
- `import type` for type-only imports (`consistent-type-imports`, a warn). In `src/shared/types.ts` and `src/preload/index.ts` the `import type` of `BannerData` / `GameBannersResult` / `ImpressionType` from `@/main/db/banners-api` is load-bearing rather than stylistic: that module value-imports `getSupabaseClient`, so downgrading it to a value import drags the main-process Supabase client into the renderer and preload bundles.
- No `any` (ESLint error). No `var`, no duplicate imports (both errors).
- Escape hatches are `/* eslint-disable rule -- reason */` with the reason after `--`. There are zero `@ts-ignore`, `@ts-expect-error` and `biome-ignore` in `src`; keep it that way.
- ESLint warns past 400 lines in a file (`max-lines`, blank lines and comments not counted; off for the generated `database.types.ts`). Split a growing module by responsibility rather than letting it pass that, and keep new files under it. The files over it were already over 400 on main, except `src/shared/types.ts`, which the Steam-bridge and plugin-host `ElectronAPI` methods took to ~440; split it (e.g. those methods into their own interface) before it grows further.
- Every `if`/`else` uses a block statement — `style/useBlockStatements` is Biome's only enabled lint rule (`preset: none`).
- Formatting: 2-space indent, 90 columns, single quotes, es5 trailing commas, always semicolons.
- Console logs carry a bracketed module tag: `[Main]`, `[Installer]`, `[Database]`, `[Migrations]`, `[SyncManager]`, `[Steam]`, `[Downloader]`, `[Proton]`, `[App]`, `[Store]`, `[useGames]`, `[Analytics]`. `console.error` in main is also captured as a Sentry event (`captureConsoleIntegration`).
- Prefer an existing dependency over a hand-rolled helper — check `package.json` (and npm) before writing one. What already covers the usual cases:
  - `@mobily/ts-belt` is the utility library: `G.isObject` / `G.isString` / `G.isArray` instead of hand-written `isRecord` guards, `F.debounce` / `F.throttle` / `F.makeControlledDebounce` / `F.makeControlledThrottle` / `F.once` / `F.memoize` instead of `setTimeout` bookkeeping, `A` / `D` / `pipe` for collections. `F.throttle` fires the first call at once and drops the rest of the window (no trailing call).
  - ts-belt has no sleep or timeout: `import { setTimeout as sleep } from 'node:timers/promises'`, and `p-timeout` (bundled, ESM-only; `fallback` instead of a rejection) for promises that take no `AbortSignal`. Steam process polling is `waitForSteamStart()` / `waitForSteamGone()` in `steam-process/lifecycle.ts`; `findSteamPids()` reads a 500 ms shared snapshot (`steam-process/snapshot.ts`) for status, host-state and endpoint reads, and takes `{ fresh: true }` for shutdown, kill and apply decisions; `isSteamRunning()` / `isSteamStopped()` and the polls always list afresh. Both are async and there is no sync variant: a sync `tasklist` blocks the main process. CDP port discovery from process arguments and `logs/webhelper.txt` is `utils/steam-cef-discovery.ts` (on Windows it needs PowerShell CIM for command lines; tasklist, behind the snapshot, has none).
  - Main-process state primitives: events go through the typed bus `appEvents` (`src/main/app-events.ts`), never a listener set or a single-slot setter. `emit()` is synchronous and a sync throw skips the remaining listeners and lands in the emitter, so a listener that can fail is `async` (`captureRejections` logs its rejection); actions and guards provided to the Steam monitor are wrapped in `safely()`, because one throw stops the actor for the session. TTL caches and fingerprint memos are `lru-cache` with `max: 1` (`fetchMethod` + `ignoreFetchAbort` when async, `memoMethod` when sync; box a `null` value). Concurrent callers share one run through `p-memoize` with `cache: false` and an explicit `cacheKey`; serial chains are `p-limit(1)`; never add `process.on('SIGINT' | 'SIGTERM')` in main, because any listener disables Node's default exit on that signal (the old Lutris handlers kept LBK alive through logout/shutdown SIGTERM); polls are `p-wait-for` (`timeout.fallback`, `resolveWith`); a child-process wait is `events.once(child, 'close', { signal: AbortSignal.timeout(ms) })`; start guards are `F.once`. The Steam monitor is the xstate machine in `src/main/steam-monitor-machine.ts`, implemented through `.provide()` in `steam-pending-actions/monitor.ts` (`pauseSteamMonitor()` is there too). Tests reset this state through the module's reset function (`resetMillenniumDetectCache()`, `resetHostFacts()`, …), `appEvents.off()` or `vi.resetModules()`.
  - Shared helpers, one home each: `errorMessage()` / `errnoCode()` (`src/shared/errors.ts`) instead of `instanceof Error` ternaries and `as NodeJS.ErrnoException` casts; `sha256()` / `sha256File()` / `sha256FileSync()` (`src/main/utils/hash.ts`); `readFileOrNull()`, `readTextOrNull()`, `readlinkOrNull()`, `realpathOrNull()`, `isPathInside()`, `isSameFile()`, `missingFiles()`, `pruneDir()` (`src/main/utils/fs-safe.ts`); `copyFileAtomic()` / `replaceDirAtomic()` next to `writeFileAtomic()`; `sendToRenderer()` (`src/main/window.ts`) for main → renderer pushes. For an async "or fallback" read write `await p.catch(() => fallback)`. Versions: `compareVersions()` (`src/shared/version.ts`, `semver` with `coerce`). File writes that must not tear: `writeFileAtomic()`. `.tar.gz`: `tar` (node-tar). `KEY=value` files such as os-release: `util.parseEnv`. Binary KeyValues: `binarykvparser`.
  - Untrusted JSON (files LBK or anyone else writes, store keys the renderer can reach, plugin messages, `binarykvparser` trees) is parsed with a `zod` schema next to its owner, types via `z.infer`; files go through `readJsonFile(file, schema)` (`src/main/utils/json-file.ts`, null on any failure). `z.object` strips unknown keys, so a record that is rewritten in place uses `.loose()` (`installationInfoSchema` in `installer/installation-info.ts`, behind `listInstallationRecords()` / `rewriteInstallationRecord()`; `installation-info.test.ts` checks the round trip); a key that must reject extras uses `z.strictObject`. `.loose()` types its output with a `Record<string, unknown>` index signature, which turns off excess-property checks, so when code also builds such a value, export the type from the plain `z.object` and apply `.loose()` only inside the parsing schema (`PendingSteamAction` in `steam-pending-actions/queue.ts`). In zod 4 a `z.unknown()` field is required unless `.optional()`. `as unknown as` is an ESLint error (`no-restricted-syntax`).
  - Branching on a closed string union is a `Record<Union, …>` table (or an exhaustive `switch` with no `default:`), so a new member is a compile error; per-OS code goes through `forCurrentOS()` tables (`steam-launcher.ts`, `steam-process/`) or the Millennium drivers. `ts-pattern` (`match(…).exhaustive()`) is kept for decisions over several fields at once (`deliveryFromBadge()` in `plugin-host/support.ts`; in the renderer `failureStep()` in `SteamPluginSetup/millenniumSetup.ts`, `outcomeStep()` in `millenniumUninstallMachine.ts`, `deckyOffer()` in `utils/pluginHostOffer.ts` and the Decky rows of `pluginHostEntries()`), not for guard clauses or single-union lookups.
  - Keep directory walkers hand-rolled: Node's `readdir({ recursive: true })` descends into symlinked directories (sync on Node 24, sync and async on Node 26).
  - `node-7z` 3.0.0 is patched (`patches/node-7z@3.0.0.patch`, pnpm `patchedDependencies`) so `$spawnOptions` reaches the child; without it `LD_PRELOAD` reaches 7z on the Deck. `archive.test.ts` checks it.
- **Фази дій — `useActionPhase` + `ActionIcon`/`AppActionIcon`.** Хук у `src/renderer/hooks/useActionPhase.ts` дубльований по суті байт-в-байт з lbk-admin і lbk-landing — правка має йти в усі три (контрактні тести лише в адмінці; тут vitest в `environment: 'node'` і без `@testing-library/react`). Таймінги: `DONE_MS` 1000 / `ERROR_MS` 1800 / `MIN_PENDING_MS` 600 у хуку, `PENDING_DELAY_MS` 100 / `SPIN_DELAY_MS` 180 / `MORPH_SPRING` в `ActionIcon.tsx`. `AppActionIcon` і `AppNumberFlow` — єдині компоненти, яким політику руху передають явно: морф іде на rAF, а number-flow на WAAPI, тож `.no-animations` їх не глушить; значення беруть із того самого `animationsEnabled`, що й `MotionConfig` у `MainLayout`. `settle()` не повертати — контрол тримає `isBusy`.
- **Іконки — два пакети, обидва потрібні.** `lucide-react` дає React-компоненти (`<Share2Icon size={20} />`) для статичних іконок, `lucide` — дані іконки (`IconNode`) для `ActionIcon`/`AppActionIcon` (`icon={Send}`), бо `morphicons` морфить саме шляхи. Дані-іконки з `lucide` імпортують як є, а React-компоненти з `lucide-react` — **завжди** через нативний експорт із суфіксом `Icon` (`<Share2Icon />`, `<XIcon />`). Так видно, що є що, і однакові імена з двох пакетів не конфліктують; власних `as`-аліасів не пишемо. Так само в lbk-admin. Емодзі в UI немає: тільки в Telegram-текстах і `console.*`.
- Domain types come from Supabase codegen: `Game`, `Platform`, `BannerType`, `FeedbackType` and `InstallPath` are derived from `src/lib/database.types.ts`. You cannot add a platform by editing `src/shared/types.ts`; the Supabase enum (`install_source`) must be regenerated first. There is no `types:generate` script — the file is generated out-of-band.
- Ukrainian copy: a translation entry is «переклад», the Steam Workshop area is «Майстерня». **Never write «айтем»** in strings, comments or copy. Install/uninstall/backup copy uses «українізатор» and the catalog/filters use «переклад» — keep each area as it is, do not mass-rename between them. Identifiers, filenames and data attributes stay English.
- Git commits: plain messages. No AI co-author or attribution trailers.

## Comments

Everyone here reads TS faster than prose about TS. **Default to no comment** — write one only for what the code can't say: a workaround and what breaks without it, a business or regulatory rule, a non-obvious ordering or idempotency constraint.

Never narrate a function body — no step-by-step, no `// Step 1:`, no `// loop over users` above a loop. No JSDoc restating the signature; types carry it. No divider or changelog comments, no commented-out code. TODOs need an issue number.

Comments that do exist stay to **one line**; never write a multi-line comment block.

**Comments are always written in English**, regardless of surrounding Ukrainian UI copy — this applies to `//` and `/* */` comments, JSDoc, and `eslint-disable` reasons alike. This is unrelated to the UI-copy rule above: user-facing Ukrainian strings (JSX text, store copy, error messages shown to the user) stay Ukrainian as always; only comments must be English.

## Testing and verification

- `pnpm test:unit` is `environment: 'node'`, `include: ['src/**/*.test.ts', 'packages/*/src/**/*.test.ts']` (no `.tsx`), and only aliases `@`; `pretest:unit` runs `pnpm build:bridge` because the ops and artifact tests read the built bundles. Suites live next to the main-process code (plus `src/shared/facet-counts.test.ts` and `version.test.ts`, and the bridge core's own in `packages/lbk-bridge-core/src/`: protocol, bridge, achievements, achievement text, the achievements page module with its navigation watcher and the Decky page injector, driven through a fake CDP socket); the built bridge bundles are checked from `src/main/utils/` (`bridge-artifacts.test.ts`, `bridge-webkit-artifact.test.ts`, `steam-bridge-ops.test.ts`); `src/renderer/store/useSubscriptionsStore.test.ts` drives the real store (stubbed `window`, mocked settings store and sounds) for the list caps; the other renderer ones cover pure helpers in `src/renderer/utils/` (`steamPluginHost`, `steamBridge`, `pluginHostOffer` with `pluginHostEntries`, `installOptions`, `installSuccess`; host-state builders in `pluginHost.fixture.ts`) and the setup-flow machines plus `millenniumSetup.ts` in `components/Modal/SteamPluginSetup/` (`createActor(machine.provide({ actors }))` with fake timers). Test-only data lives in `*.fixture.ts` next to the tests that import it (`pluginHost.fixture.ts`, `packages/lbk-bridge-core/src/steam-beta-achievements.fixture.ts`, recorded from the Steam beta with account data replaced); production code never imports a fixture. **There are no component or hook tests** — do not assume this command covers UI changes. Testing a component requires editing `vitest.config.ts` (jsdom, `.tsx` glob, `@renderer`/`@components`/`@store` aliases).
- Write table cases as `it.each` rows rather than a run of `expect`s or a loop in one `it`; the first column names the case (a label, or the input or expected error itself when it reads as one), and each rejection case gets its own row so a failure names it.
- `pnpm test:e2e` needs a packaged app at `release/<package.json version>/` — bump the version without re-packaging and it fails with "Release directory not found". Port 19222 must be free; on Linux you need a display.
- **E2E is strictly serial.** `e2e/playwright.config.ts` pins `workers: 1` (with `retries: 1`, `trace: 'on-first-retry'`) and every spec launches its own packaged app in `beforeAll`, all bound to the same hard-coded CDP port — `launchApp()` force-kills whatever holds it. Never add `fullyParallel` or `test.describe.configure({ mode: 'parallel' })`; a second instance cannot get a port.
- **E2E selects on Ukrainian visible text and ARIA**, e.g. `getByPlaceholder('Пошук гри...')`, `getByText('Ігор не знайдено')`, `button[title="Налаштування"]`, `#modal-title`, `.drag-region`, `[data-nav-group="game-list"]`. There is not one `data-testid` in `src` or `e2e/tests`. Renaming that copy, dropping the settings gear's `title`, or changing `Modal.tsx`'s `id` breaks e2e, which runs on every PR (`e2e.yml` also calls `ci.yml`).
- `test/games.json` is a **dev-only hot-reload catalog override** watched by `games-repository.ts`, not a vitest fixture.
- `pnpm type-check` does not cover `e2e/` (own tsconfig, never invoked) and does not cover `electron.vite.config.ts`: `tsconfig.json` includes only `src`, and the referenced `tsconfig.node.json` lists `vite.config.ts` (which does not exist) and `vitest.config.ts` — and project references are not built by a bare `tsc --noEmit`. Verify before relying on either being checked.

## Build, release, secrets

- `resources/extensions/spellfix.{dylib,so,dll}` is compiled by `scripts/build-spellfix.js` from `resources/extensions/spellfix.c`, is gitignored (`resources/extensions/*` with a `!*.c` negation), and is a hard `extraResources` requirement — `pnpm dist:*` without a prior prebuild has nothing to copy. `pnpm build` only triggers it because `pnpm-workspace.yaml` sets `enablePrePostScripts: true`. Windows needs MSVC (`cl.exe` located via vswhere). `isUpToDate()` compares mtimes only, so a stale binary survives a better-sqlite3 upgrade — delete it by hand after upgrading.
- At runtime a missing spellfix degrades gracefully: search just loses typo tolerance.
- `VITE_*` values are inlined by Vite **into the main process too** (`src/main/db/supabase-credentials.ts`, `src/main/game-detector/kurin.ts`, `src/main/index.ts`). Rotating the Supabase anon key silently breaks every already-shipped binary until a rebuild and release. `.env.example` lists the keys; `.env` is gitignored.
- Every platform `files` in `electron-builder.config.cjs` is the full `appFiles()` list (`out/**/*` plus exclusions). A platform `files` replaces the root list as the app matcher, and a list of exclusions alone makes electron-builder add `**/*` and pack the whole repo (`.env`, `src/`, earlier `release/` builds) into `app.asar`.
- `verifyUpdateCodeSignature: false` in `electron-builder.config.cjs` is deliberate (Azure Trusted Signing's root ships via a Windows Update many users lack). Do not "fix" it. Windows signing only activates when `AZURE_TENANT_ID` is set, so local `dist:win` is unsigned by design.
- Two update paths: electron-updater, and a portable-only `latest.yml` poller (`src/main/portable-updater.ts`) that emits the same `update-available` event with an extra `downloadUrl`.
- `LBK_E2E=1` or `--e2e` sets `remote-debugging-port=19222` and disables Sentry and all tracking. The port is a bare literal in three places — `src/main/index.ts`, `e2e/helpers/launch.ts`, `e2e/tests/clear-cache.spec.ts` — change all of them.
- Release is tag-driven (`push: tags: v*.*.*`): draft release → per-OS build with `--publish never` → E2E on the packaged app → `gh release upload --clobber` from `release/<package.json version>`, so a version/tag mismatch uploads nothing. Linux targets are AppImage + rpm; the AUR job downloads `LBK-Launcher-linux.AppImage` by name.

## Do not

- Do not write user-visible text as a literal — not in JSX, main-process messages, notifications, errors or tray menus. Add a key to `packages/lbk-i18n/src/uk.ts` and call `t('…')`, even for one word.
- Do not add a `games` column without all five edits — `pnpm type-check` catches only two of them.
- Do not write a games-listing query without `VISIBLE_GAMES_SQL`.
- Do not put a read or a search on the DB worker — it handles writes only.
- Do not assume a migration ran on a fresh install; it runs on the second launch.
- Do not call `window.electronAPI.checkForUpdates()` — `check-for-updates` has no main handler. `ipcMain.on('windows: restore')` in `window-controls.ts` has a typo'd name no preload code invokes.
- Do not use `localStorage` in LBK's renderer, or `React.lazy` (used nowhere — the cold-start strategy is `isOpen`-gated modals, `useIdleEffect`, `ShaderWarmup`, and deferred image decode).
- Do not edit `localconfig.vdf` while Steam is running, and do not replace the atomic tmp+rename write.
- Do not skip `resignMacBundles()` on macOS installs.
- Do not move the Linux Chromium switches lower in `src/main/index.ts`.
- Do not rewrite or trim `src/shared/changelog.json` — it is append-only. Add the entry for version N **before** tag `vN` is cut: `src/main/changelog.ts` fetches the file as it existed at that tag, so a later commit is invisible forever. It currently holds 2.22.0 and 2.23.0, so the practical history starts at 2.22.0. `changelog.ts` returns `undefined` on a failed fetch, so its `lru-cache` stores nothing and the next `update-available` (every 30 min) retries.
- Do not edit files not covered by tooling and assume CI caught it: Biome sees only `src/**` (minus `src/lib/database.types.ts`), `packages/**` plus `electron.vite.config.ts`, `vitest.config.ts`, `package.json` and `tsconfig*.json` (`e2e/` and `scripts/` are unformatted), and ESLint ignores every `*.js`/`*.cjs`/`*.mjs` (so `rollup.config.js` and `build.mjs` in `packages/` are unlinted).
